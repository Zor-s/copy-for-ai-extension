# Output Format

This document details the structured text format generated by `src/services/formatter.ts` and explains why this schema is optimized for Large Language Model (LLM) processing.

---

## 1. Format Schema Specification

When copying multiple workspace files, the formatter concatenates them into a single string. Each file block is wrapped inside plain-text header and footer boundaries:

```text
===== FILE: relative/path/to/file.ext =====

[Raw, unescaped file contents]

===== END FILE: relative/path/to/file.ext =====

```

* **Delimiters:** Five equal signs (`=====`) on either side of the file declaration.
* **Case Sensitivity:** Structural tags (`FILE:`, `END FILE:`) are strictly uppercase.
* **File Path:** The relative path of the file from the workspace root is used, maintaining consistency with your project structure.
* **Spacing:** A single blank line separates the header from the contents, the contents from the footer, and two blank lines (`\n\n`) separate consecutive file blocks.

---

## 2. Structural Example

If you select `src/extension.ts` and `src/services/clipboard.ts` in your workspace, the resulting clipboard output will look exactly like this:

```text
===== FILE: src/extension.ts =====

import * as vscode from "vscode";
import { copyCommand } from "./commands/copy";

export function activate(context: vscode.ExtensionContext) {
    context.subscriptions.push(
        vscode.commands.registerCommand(
            "copyForAI.copy",
            copyCommand
        )
    );
}

export function deactivate() {}

===== END FILE: src/extension.ts =====

===== FILE: src/services/clipboard.ts =====

import * as vscode from "vscode";

export async function copyToClipboard(text: string) {
    await vscode.env.clipboard.writeText(text);
}

===== END FILE: src/services/clipboard.ts =====

```

## 3. Why This Format is Optimized for LLMs

The plain-text tag approach is selected over JSON, XML, or Markdown formatting for several reasons:

### 🌟 No Escape Collision

Using JSON or Markdown code blocks (`````) to wrap source code can cause parsing issues if the source code itself contains triple backticks, unescaped quotes, or JSON brackets. This format safely encapsulates any code characters without needing to escape them.

### 🌟 Minimal Token Overhead

The headers and footers add only a few characters per file, saving valuable context window space compared to verbose formats like JSON schemas or nested XML nodes.

### 🌟 High Parseability

The equal sign dividers (`=====`) create a strong visual and mathematical semantic break in the BPE (Byte-Pair Encoding) attention layer of modern LLMs. This makes it easier for the AI to isolate individual file contexts, locate code boundaries, and write accurate modifications.
